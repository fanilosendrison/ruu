## Integrated decision

ADR-070 makes the intended product definition and user experience a normative governing architectural contract. The package now states explicitly that **`ruu` is Git-based version control redesigned for agentic software development**.

The consolidated specification now begins with `# 0. Product intent — governing user experience`, before the technical Purpose/mental-model/invariant sections. Its first normative subsection defines the architectural center of gravity:

```text
agentic version-control semantics
        ↓
exact native Git state / history
        ↓
provider/route realization when required
```

Remote hosting/provider publication (PRs, stacks, merge queues, protected-target APIs, provider review state) is explicitly an extended feature layer over the core rather than the definition of the product. Removing provider APIs must still leave a meaningful native-Git agentic version-control core. Provider objects must not become the source of core version identity or convergence truth where those facts can be established independently.

The section then states explicitly that ordinary use supports:

```text
multiple concurrent coding sessions
sessions started from different managed repositories
one session touching one or many repositories
overlap on the same repository / ConvergenceUnit / files
plain Ruu invocation from any managed repo in the discovered domain
no user-level mutex
no caller-authored global repository list
no caller-authored PromotionGroup membership
no caller-authored stack/dependency topology
no manual invocation ordering for correctness
mechanical reconciliation of stale/compatible concurrent work
semantic escalation only for irreducible conflict or missing authority
```

The section also makes clear that hands-off concurrency does not authorize surprise mutation of externally owned active worktrees and does not turn ordinary Git into a hidden command protocol.

ADR-070 supplies the conflict rule: prior technical clauses are interpreted in the product-conformant way when possible and are superseded only to the minimum extent necessary if they directly conflict. A future intentional product regression/change must explicitly `Amends: ADR-070`, identify the user-visible tradeoff, and update §0 Product intent in the same decision.

## Companion-contract integration

`EXTERNAL-CONTROL-PLANE-CONTRACT.md` now contains `§1.1 Product-intent conformance`.

It explicitly distinguishes system metadata from user orchestration: durable `invocation_id`, sealed ContributionUnit cohort, target/group bindings, and similar authority metadata are carried/generated by the Development System/ECP behind the user-facing invocation. They are not a requirement that the human reconstruct internal topology before running `ruu`.

It also states that provider submissions/review/merge-queue/protected-target objects are realization/projection facts over core exact Git/version state rather than the source of provider-independent core identity.

## Hostile product-intent pass

`HOSTILE-AUDIT-ADR070.md` checks the following adversarial scenarios:

```text
three simultaneous sessions invoked from different repos
one multi-repo cohort invoked while caller sits in only one repo
two sessions contributing to the same ConvergenceUnit
simultaneous Ruu calls
newer managed work appearing while another producer still owns its worktree
ordinary branch deletion during managed history
proposed mandatory --group/--repos/--depends-on flags
proposal to define the product primarily around GitHub/PR/provider objects
irreducible semantic conflict
```

Verdict: **PASS WITH EXPLICIT GOVERNANCE**.
